# AZIRAL Product Video

Show a product's starting state, one main action and its visible result. This independent AZIRAL workflow adds product-story planning to the HyperFrames framework maintained by HeyGen.

## Start from evidence

Work from the supplied recording, screenshots, approved descriptions and requested output. Separate visible behavior, described capabilities and illustrative concepts in the brief. Use the first two for factual claims; label concepts. Leave out unsupported customer numbers, time savings, endorsements and platform availability.

Use [the brief template](references/brief-template.md) when inputs are incomplete or variants need to stay aligned. Preserve the user's duration, format, language and sound choices. A planning request only needs a plan.

## Choose the demonstration

Choose one workflow the viewer should understand. Map its starting state, main action and result to actual source frames before choosing effects. Keep the product UI large enough to inspect. Guide attention toward the active control instead of shrinking the screen into a decorative frame.

For each shot, record its source, approximate duration, action, on-screen text and supporting evidence. Give the viewer time to locate the control and recognize the changed state. If copy does not fit, reduce the message or adjust the hold within the brief before reducing its font size.

For language variants, preserve the action and evidence. Translate meaning, then adapt line breaks and holds to each version. Test Cyrillic and Kazakh characters in the actual font. Preserve product names and source UI labels when the application is not localized. A translated video does not establish that the application supports that language.

## Compose and verify

Use the installed HyperFrames version's [official documentation](https://hyperframes.heygen.com/introduction) and CLI help for current composition syntax. This skill does not bundle the engine or replace its API documentation.

Drive animation from explicit timeline time so previews and rendered frames agree. Make fonts and media available locally for the final render. For another aspect ratio, choose an intentional crop or separate composition and check that controls, text and the result remain visible.

Inspect the starting state, action, result and final frame in every requested variant. Check for clipped text, missing glyphs, tiny UI, unintended private data in recordings, missing media and black frames. Run the installed framework's relevant composition checks before rendering. Confirm playback, dimensions and duration of the delivered file.

## Deliver the requested result

Provide the requested plan or video and editable composition when produced. Record asset origins, reuse permissions and any unresolved evidence gap. Prefer local rendering. Paid generation, hosted rendering and external publication require the user's existing authorization for the service and cost.
