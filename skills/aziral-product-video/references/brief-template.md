# Product-demo brief

Use this template for incomplete inputs or several language and format variants. Keep unknown values explicit.

```text
Product and owner:
Audience:
One action the viewer should understand:
Deliverable: plan, editable composition, rendered file, or a combination
Duration and aspect ratio:
Languages:
Sound: supplied audio, requested voice/music, or silence

Evidence:
- Recording or screenshots:
- Approved capability description:
- Claims the sources support:
- Unverified claims to omit:
- Concept-only elements, if any:

Assets:
- File or URL:
- Origin and permitted use:
- Private information to hide before rendering:

Shots:
1. Starting state - source, duration, crop, text
2. Main action - source, duration, crop, text
3. Visible result - source, duration, crop, text

Variants:
- Language: translated copy, product-name spelling, font/glyph check
- Aspect ratio: composition/crop, text-safe area, UI readability

Delivery:
- File opens and matches requested dimensions and duration.
- Main control and result are readable at the intended viewing size.
- Text fits each language and format.
- No accidental private data, missing media or black frames.
- Asset origins and factual sources are recorded.
```

## Timing and language decisions

Use the footage as the timing source. Let the viewer find the active control before the action, then recognize the changed state afterward. If several actions are essential, identify the larger workflow and give each action a readable beat.

Lay translated copy out before duplicating timing. Longer text may need a new line break or hold. A mobile version may need fewer simultaneous labels than a landscape version.

## Missing assets

Identify which missing assets are essential for the requested output. A storyboard can remain useful while source footage is unavailable. Record that gap rather than substituting invented product behavior.
